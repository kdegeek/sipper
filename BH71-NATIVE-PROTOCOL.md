# BH71 native caller-ID transport

This implementation was derived from local IOKit traffic generated by synthetic calls and corroborated against exported SDK method implementations. It targets only USB VID `6993`, PID `b07e`, telephony usage page `0b`, usage `05`. No firmware, pairing, persistent device configuration, shell commands, authentication bypass, or copied vendor implementation is involved.

## Envelope

Output report C8 is 1024 bytes, zero padded. Fields are little endian:

| Offset | Width | Meaning |
|---|---|---|
| 0 | 1 | Report ID C8 |
| 1 | 1 | Command transfer 13 |
| 2 | 2 | 16 + payload length |
| 4 | 2 | Command |
| 6 | 2 | Transaction tag |
| 8 | 4 | Payload length |
| 12 | 4 | Parameter A |
| 16 | 4 | Parameter B |
| 20 | variable | Payload |

Responses repeat the command and tag. A is usually status zero; heartbeat is an exception. Some responses advertise zero payload length despite returning a fixed structure after byte 20, so each operation validates its actual minimum report length. The transport correlates both opcode and transaction tag.

## Session and call commands

| Command | A | B | Payload/result |
|---|---|---|---|
| 0276 | 1 register / 0 unregister | 0 / session | 160-byte identity; name[32], version[4], flag 1 at offset 36. Registration returns session in B. |
| 0283 | session | 50 | Returns start and end call IDs as two uint16 values at byte 20. |
| 0277 | 1 alive / 0 stop | session | Heartbeat every three seconds. |
| 0239 | 1 subscribe / 0 unsubscribe | process ID | Enables vendor call-control events. |
| 0285 | session | call ID | 54-byte call state; see below. |
| 0286 | session | call ID | Readback of call state at byte 20. |
| 0237 | 0 | 8 mute / 9 unmute | Applies headset mute, in addition to displayed call state. Fire-and-forget; no reply. |
| 022c | 4 | call ID | 300-byte contact: UTF-8 name[200], number[100], both NUL terminated. |

Call-state payload: session uint16 at 0; call ID uint16 at 2; phase at 4; mute at 6; direction at 7 (2 incoming, 1 outgoing). Phases: active 1, held 2, dialing 4, incoming 5, removed 6. Removed calls read back as phase zero. Unused fields are zero, never replayed from captures (the SDK emits uninitialized padding).

## Button and touchscreen requests

Vendor input report C8, transfer 3B, event 0041 at offset 4, payload length 54 at offset 6, contains a call action at offset 8. Its session is uint16 at 8, call ID uint16 at 10, and action uint16 at 12. Actions: answer 1, end 2, hold 3, resume 4, reject 5, mute 8, unmute 9. **These are action codes, not the display phase enum above.** The session and call ID must match an active local mapping. Sipper validates/deduplicates the action against its current call state and sends an authoritative snapshot. Merely displaying the call without this round trip leaves the workstation waiting for a response.

Ordinary telephony report 04 remains available as a fallback. The same state-aware reducer deduplicates requests from either path. All caller metadata travels only over private child-process pipes and USB; helper diagnostics omit names and numbers.

## Limits

Observed on this connected BH71 and its current firmware. Other models, firmware variants, audio routing, and phone-originated calls are outside this adapter's scope. A native binary removes the Rosetta dependency; it does not constitute validation against an unreleased macOS version.
